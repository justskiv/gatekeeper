# Доменная модель

Чистые value-типы бизнес-модели без инфраструктуры. Читаемое зеркало спеки `access-domain`.

## Граница зависимостей

`internal/domain` содержит только value-типы и константы бизнес-модели. Без поведенческих интерфейсов, без зависимостей от инфраструктурных пакетов проекта. Его импорты ограничены stdlib, нужной для value-типов (сейчас — `time`). Нижние слои (config, store, bot, integration) импортируют `domain`; обратных импортов из `domain` нет.

## Источники подписки

Платформы — Boosty, Tribute и manual. Состояния подписки — active и expired. Подписка несёт: Telegram user ID, платформу, статус, временные метки периода, опциональные внешние идентификаторы, tier и signal-метаданные.

## Итоговый статус доступа

Вердикт источника и итоговый статус доступа выражаются значениями active, inactive, unknown. Объяснение решения о доступе — один или несколько reason'ов, каждый с источником, вердиктом, человекочитаемой деталью и опциональным временем истечения.

## Доступ к управляемым ресурсам

Модель покрывает управляемые клубные ресурсы, состояния invite-ссылок, состояния grant'ов и pending-отзывы — то, что понадобится будущему Telegram-enforcement. Grant фиксирует ресурс, состояние, источник допуска, время вступления, время и причину отзыва.
