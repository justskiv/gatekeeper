## MODIFIED Requirements

### Requirement: Background subsystems run under a supervised errgroup

Фоновые подсистемы MUST запускаться под `errgroup.WithContext`: поллер
или Telegram webhook transport, optional HTTP server, Enforcer workers,
periodic Reconciler и cleanup ticker. Первая фатальная ошибка любой
подсистемы или сигнал отменяют общий контекст и останавливают остальных.
Порядок остановки: отмена контекста -> graceful HTTP shutdown ->
дождаться завершения горутин -> `db.Close()` в самом конце (закрывать
БД, пока живы писатели, нельзя).

Ни одна подсистема MUST NOT возвращать `nil`, пока её контекст жив. Возврат
`nil` означает штатное завершение и MUST быть следствием отмены контекста;
любой другой выход MUST возвращать ошибку, чтобы группа отменилась и процесс
завершился ненулевым кодом. Решение о том, штатная ли это остановка, MUST
приниматься по состоянию контекста, а не по идентичности ошибки.

Enforcer MUST супервизировать свои воркеры: каждый выход воркера MUST
логироваться с причиной, воркер MUST перезапускаться с backoff, а устойчивая
невозможность удержать воркера в работе MUST эскалироваться в возвращаемую
ошибку. Enforcer MUST логировать старт и остановку пула. Одновременное
завершение всех воркеров при живом контексте MUST порождать ошибку, а не
восприниматься как штатное завершение группы.

«Устойчивая невозможность» MUST измеряться как частота, а не как сумма за всё
время жизни процесса: бюджет перезапусков — это «не более N за окно W», и
перезапуски, вышедшие за границу окна, MUST переставать учитываться. Счётчик,
который обнуляется только после запуска, прожившего целое окно, накапливает
редкие одиночные сбои и в итоге убивает процесс, работавший при этом штатно.
Сброс backoff и истечение бюджета MUST решаться раздельно: первый отвечает на
вопрос «смог ли воркер продержаться», второй — «как часто он падает».

Поллеру отдельная финализация offset не нужна: `update_offset` durable
после каждого батча. Reconciler и cleanup ticker MUST завершаться по context
cancellation без удержания DB transaction. HTTP server MUST stop accepting new
requests during shutdown and allow in-flight requests to finish until
its shutdown context expires.

#### Scenario: Ошибка поллера отменяет группу
- **WHEN** горутина поллера возвращает ошибку
- **THEN** контекст группы отменяется
- **AND** Enforcer, Reconciler, cleanup и HTTP server завершаются
- **AND** ошибка пробрасывается в `main`

#### Scenario: Ошибка HTTP server отменяет группу
- **WHEN** HTTP server возвращает ошибку, отличную от normal shutdown
- **THEN** контекст группы отменяется
- **AND** poller/webhook transport, Enforcer, Reconciler и cleanup
  завершаются
- **AND** ошибка пробрасывается в `main`

#### Scenario: Ошибка Enforcer отменяет группу
- **WHEN** горутина Enforcer возвращает ошибку, несовместимую с
  продолжением работы
- **THEN** контекст группы отменяется
- **AND** poller/webhook transport, Reconciler, cleanup и HTTP server
  завершаются
- **AND** ошибка пробрасывается в `main`

#### Scenario: Смерть всех воркеров при живом контексте не молчит
- **WHEN** все воркеры Enforcer завершились, а контекст группы не отменён
- **THEN** `Enforcer.Run` возвращает ошибку
- **AND** контекст группы отменяется и процесс завершается ненулевым кодом
- **AND** причина выхода каждого воркера присутствует в логе

#### Scenario: Упавший воркер перезапускается и это видно в логе
- **WHEN** отдельный воркер Enforcer завершился с ошибкой при живом контексте
- **THEN** он перезапускается с backoff
- **AND** факт выхода и причина попадают в лог
- **AND** пул продолжает обрабатывать очередь

#### Scenario: Редкие перезапуски не исчерпывают бюджет
- **WHEN** воркер падает и перезапускается реже, чем раз в окно политики
- **THEN** бюджет перезапусков не исчерпывается, сколько бы времени процесс ни
  работал
- **AND** процесс продолжает работу

#### Scenario: Частые перезапуски всё ещё эскалируются
- **WHEN** число перезапусков внутри одного окна превышает бюджет
- **THEN** `Enforcer.Run` возвращает ошибку с причиной последнего выхода
- **AND** контекст группы отменяется

#### Scenario: Ошибка Reconciler pass не ломает процесс при recoverable alert
- **WHEN** Reconciler обнаруживает потерю прав или `unknown` source
- **THEN** создаётся `admin_alert`
- **AND** подсистема продолжает работу, если ошибка recoverable

#### Scenario: Сигнал дожидается горутин до закрытия базы
- **WHEN** процесс получает сигнал завершения
- **THEN** контекст отменяется, HTTP server выполняет graceful shutdown,
  а горутины Enforcer, Reconciler, cleanup и poller/webhook transport
  возвращаются
- **AND** `db.Close()` выполняется только после остановки горутин
