## ADDED Requirements

### Requirement: Enforcer exposes a liveness snapshot of its worker pool

Enforcer MUST публиковать point-in-time снимок состояния своего пула,
доступный процессу без обращений к БД и сети. Снимок MUST содержать:

- `WorkersConfigured` — размер пула, с которым Enforcer собран;
- `WorkersAlive` — число горутин, находящихся сейчас в цикле воркера;
- `WorkersStale` — число воркеров, чья последняя завершённая итерация старше
  порога залипания;
- `MaxCycleAge` — возраст самого старого heartbeat среди всех воркеров;
- `Restarts` — сколько раз любой воркер был перезапущен.

Heartbeat MUST вестись **на каждый воркер отдельно**, а не один на пул: общий
timestamp оставался бы свежим, пока один воркер заклинен, а остальные работают,
и делал бы главный режим отказа ненаблюдаемым.

Heartbeat воркера MUST обновляться на **каждой завершённой итерации цикла,
включая холостые** — то есть итерации, в которых очередь оказалась пуста, и
итерации, в которых действие ушло в retry или в `dead`. Утверждаемый факт —
поворот цикла, а не наличие или успех работы: пустой outbox является нормальным
режимом и MUST NOT читаться как отказ. Heartbeat воркера MUST также
обновляться при его старте, чтобы перезапущенный воркер не наследовал
залипание предыдущего.

Вердикт liveness MUST выноситься по свежести heartbeat, а не по числу живых
горутин: воркер, заклиненный внутри Telegram-вызова, остаётся живой горутиной,
неотличимой от работающей. Пул MUST считаться живым тогда и только тогда, когда
`WorkersStale == 0`. `WorkersAlive` MUST оставаться диагностическим полем и
MUST NOT участвовать в вердикте.

Порог залипания MUST быть константой пакета, а не элементом конфигурации, и
MUST стоять выше худшей законной итерации (ожидание rate-limiter'а плюс
несколько последовательных HTTP-таймаутов клиента Telegram).

#### Scenario: Работающий пул сообщает о себе как о живом
- **WHEN** все воркеры Enforcer поворачивают цикл
- **THEN** снимок сообщает `WorkersConfigured`, равный размеру пула
- **AND** `WorkersStale` равен нулю
- **AND** `MaxCycleAge` меньше порога залипания
- **AND** вердикт liveness — «жив»

#### Scenario: Холостой цикл при пустой очереди остаётся прогрессом
- **WHEN** outbox пуст и воркеры не выполняют действий
- **THEN** heartbeat каждого воркера обновляется на каждой итерации
- **AND** `WorkersStale` остаётся нулём
- **AND** вердикт liveness — «жив»

#### Scenario: Заклиненный воркер выявляется, хотя горутина жива
- **WHEN** один воркер не завершил ни одной итерации дольше порога залипания,
  а остальные продолжают работать
- **THEN** `WorkersStale` больше нуля
- **AND** `MaxCycleAge` больше порога залипания
- **AND** вердикт liveness — «не жив», несмотря на то что число живых
  горутин воркеров не изменилось

#### Scenario: Перезапуск воркера виден в снимке
- **WHEN** воркер завершился при живом контексте и был перезапущен
- **THEN** `Restarts` увеличивается
- **AND** heartbeat перезапущенного воркера обновляется при старте
- **AND** пул не считается залипшим из-за паузы на backoff

#### Scenario: Снимок не выполняет внешних обращений
- **WHEN** снимок состояния пула запрашивается
- **THEN** он вычисляется по внутрипроцессному состоянию
- **AND** ни база данных, ни Telegram API при этом не опрашиваются
